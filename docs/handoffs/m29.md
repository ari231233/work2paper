# M29 交接记录：多源分层文献检索

> 状态：已完成并验证｜任务卡提交：`2e046ac`

## 1. 用户目标

- 每个研究方向至少展示约 7–8 篇真实论文。
- 高度垂直论文不足时允许补充部分相关论文，但必须明确区分证据强度。
- 允许增加公开检索源，并自动合并不同来源中的重复论文。

## 2. 核心实现

- 检索源由 2 个扩展为 5 个：arXiv、Semantic Scholar、OpenAlex、Crossref、DBLP。
- 五个来源在单轮内并行请求；任一来源失败、限流或超时只跳过该来源。
- 每个来源每轮最多取 8 篇；单方向最终目标 8 篇、最多展示 12 篇。
- 第一层使用原始聚焦查询；不足时用确定性策略生成最多 3 个由窄到宽的扩展查询，不新增 LLM 调用。
- 论文按 DOI、arXiv ID、规范化标题跨源去重；同一论文合并 `source_records` 和缺失元数据。
- 缓存 schema 升为 v2，缓存键包含策略版本，旧版少结果缓存不会继续生效。

## 3. 兼容字段

没有修改 Dossier 顶层 schema、检索冻结函数签名或 Agent 接口。`papers[]` 增加兼容字段：

```text
relevance_level: high | partial
match_reason: 命中的核心术语或扩展检索说明
source_records: 合并后的来源列表
doi: DOI（如来源提供）
```

`literature[]` 增加展示辅助字段：

```text
target_count / high_count / partial_count
coverage_status: sufficient | insufficient
```

## 4. Web 展示

- Query 标题区显示“共 N 篇 / 目标 8 篇”和“覆盖基本充足 / 证据覆盖不足”。
- 同时显示高度相关和部分相关论文数量。
- 论文卡使用中文标签“高度相关 / 部分相关 / 背景参考”。
- 显示匹配依据及合并后的来源；论文有 URL 时标题可直接打开原页面。
- 旧 run 没有 M29 字段时继续使用原前端推导逻辑，保持向后兼容。

## 5. 真实网络验证

使用全新缓存、NullProvider（不调用 LLM）测试三个方向：

| 研究方向 | 去重后展示 | 可用来源 |
|---|---:|---|
| eVTOL obstacle avoidance flight control | 12 | OpenAlex / Crossref / Semantic Scholar |
| prescribed performance trajectory tracking control | 12 | OpenAlex / Crossref / Semantic Scholar / DBLP |
| industrial remaining useful life prediction anomaly detection | 12 | OpenAlex / Crossref |

OpenAlex 与 Crossref 单独测试均能返回 8 篇；DBLP 对过窄查询返回 0 时不会导致整项检索失败。

## 6. 降级与边界

- 所有来源不可用时仍返回空 papers 和明确的离线/无结果说明，不虚构论文。
- 最终不足 7 篇时标记 `coverage_status=insufficient`，不复制论文凑数。
- “部分相关”只要求命中至少一个核心术语，因此只能作为背景证据，不能与高度相关证据等权支撑 novelty 结论。
- Crossref/DBLP 部分记录没有摘要；文献理解会沿用现有确定性降级，不编造缺失实验信息。
