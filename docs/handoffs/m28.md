# M28 交接记录：主流科研文档解析与中英文 OCR

> 状态：已完成｜任务卡提交：`e31213a`｜实现提交：本提交

## 1. 本次解决的问题

- 旧实现对所有 `doc` 资产直接按 UTF-8 容错读取，PDF 二进制可能产生偶发关键词，DOCX/PPTX 则无法得到正文。
- 项目理解 Agent 过去只收到“命中某标签几次”的摘要，无法看到论文标题和摘要，容易把关键词噪声扩写成与项目无关的叙事。

## 2. 已实现能力

- PDF：使用 PDFium 提取文本层；页面无足够文本时渲染并执行本地中英文 OCR。
- DOCX：提取段落、表格、页眉页脚；内嵌图片执行 OCR。
- PPTX：逐页提取文本、表格、演讲者备注；内嵌图片执行 OCR。
- 纯文本、Markdown、RST、LaTeX 保持原有接口和行为。
- 文档损坏、解析依赖缺失、单页或单图 OCR 失败均安全降级，不中断项目其他文件。

## 3. 依赖与安装

- 新增 `documents` extra；`web` extra 同时包含这些依赖。
- 依赖：`pypdfium2`、`python-docx`、`python-pptx`、`rapidocr-onnxruntime`、`Pillow`。
- OCR 模型随 Python 包在本地运行，不要求另装 Tesseract，不调用云端 OCR。
- Windows 代理与国内镜像安装示例已写入首页 README。

## 4. 识别质量与安全策略

- 单文档默认预算：20 万字符、100 页、60 张内嵌图片、单图最多 1200 万像素；超限保留已提取内容并记录提示。
- 文档正文按内容哈希去除完全重复副本；主目录和较浅层级的稿件优先，`archive/backup/tmp/old` 等历史副本降权。
- 最多选择 12 条正文摘录、8 条解析提示和 40 条关键词证据发给项目理解 LLM，避免重复论文撑爆上下文。
- 正文摘录会脱敏邮箱及常见凭据形式；完整文档和原始图片不发送给 LLM。
- 英文关键词统一使用词元边界，消除 `context → text`、`default → fault` 一类误命中。

## 5. 接口与兼容性

## 7. 降级与遗留边界

- 未安装 `documents` extra 时，纯文本和代码仍可分析；PDF/DOCX/PPTX 返回“缺少文档解析依赖”诊断，不会把二进制当文本。
- 加密 PDF、严重损坏的 Office 文档保留诊断但不尝试破解或修复。
- 当前只支持主流 `.pdf/.docx/.pptx`；旧 `.doc/.ppt` 按用户确认不纳入 M28。
- OCR 识别图表中的文字，但不会理解图形关系、公式结构或图表视觉语义。
